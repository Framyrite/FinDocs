# FinDocs Frontend

Десктопный интерфейс FinDocs на React, TypeScript и Vite.

Приложение позволяет загружать учебные материалы, выбирать документы для поиска, задавать вопросы и просматривать источники ответов. Текущий MVP поддерживает TXT-файлы.

## Требования

- Node.js 22.12+ или совместимая актуальная LTS-версия.
- npm.
- Запущенный backend FinDocs для работы через реальный API.

Подготовка backend, его зависимости и конфигурация описаны в `backend/README.md`.

## Локальный запуск

Команды ниже выполняются из корня репозитория, если явно не указано другое.

### 1. Установить зависимости frontend

```powershell
cd frontend
npm ci
```

### 2. Создать локальный файл окружения

Если файла `frontend/.env` ещё нет:

```powershell
Copy-Item .env.example .env
```

Для работы через локальный Vite dev proxy в `.env` должно быть:

```dotenv
VITE_API_BASE_URL=/api
```

После изменения `.env` необходимо перезапустить Vite.

### 3. Проверить режим API

В `src/api/index.ts`:

```typescript
const USE_MOCK = false;
```

При таком значении frontend выполняет реальные HTTP-запросы к backend.

### 4. Запустить backend

В отдельном терминале запустите backend согласно `backend/README.md`.

Локальная конфигурация frontend ожидает API по адресу:

```text
http://127.0.0.1:8000
```

В проверенном локальном сценарии backend использует `FINDOCS_LLM_PROVIDER=mock`. Это серверный MockLLM: загрузка, хранение, обработка документов и поиск при этом выполняются реальным backend.

### 5. Запустить frontend

Из папки `frontend`:

```powershell
npm run dev
```

Откройте адрес из вывода Vite, обычно:

```text
http://localhost:5173/
```

Backend и frontend должны продолжать работать в отдельных терминалах.

## Как frontend обращается к backend

Браузер отправляет запросы на `/api/...` своего Vite-сервера. Dev proxy из `vite.config.ts` перенаправляет их на локальный FastAPI, удаляя префикс `/api`.

Например:

```text
/api/documents → http://127.0.0.1:8000/documents
```

Это локальный прокси для разработки; VPN для него не нужен.

Dev proxy работает при `npm run dev`. Для production необходимо отдельно настроить маршрутизацию API или адрес API и CORS. Команда `npm run preview` не заменяет настройку production-развёртывания.

## Режим frontend mock

Для работы без backend можно установить в `src/api/index.ts`:

```typescript
const USE_MOCK = true;
```

Frontend mock:

- хранит данные в памяти страницы;
- имитирует задержки запросов и изменение статусов;
- использует демонстрационные ответы и источники;
- не выполняет реальный поиск по содержимому загруженных файлов;
- теряет данные при обновлении страницы.

`USE_MOCK` и `FINDOCS_LLM_PROVIDER` относятся к разным уровням приложения. Серверный MockLLM не означает, что frontend работает через заглушку.

## Реализованные сценарии

### Библиотека документов

- Список документов на всю доступную ширину, без папок.
- Поиск по названию без учёта регистра.
- Отображение названия, размера, статуса, даты и времени загрузки.
- Статус расположен по центру строки документа; дата и время находятся в одной строке.
- Удаление документа через меню с тремя точками и подтверждение.
- Отдельные состояния пустой библиотеки и отсутствия совпадений при поиске.
- Обновление промежуточных статусов через polling.
- Ошибка проверки статуса и возможность повторить проверку отделены от ошибки обработки самого документа.

### Статусы документов

На уровне API и типов сохранены все четыре статуса:

| Статус API | Отображение в текущем интерфейсе |
| --- | --- |
| `uploaded` | Жёлтая плашка «Обработка», пояснение об ожидании обработки при наведении |
| `processing` | Жёлтая плашка «Обработка» |
| `ready` | Зелёная плашка «Готов» |
| `error` | Красная плашка «Ошибка» с причиной |

Контракт предусматривает отдельную подпись «Загружен» для `uploaded`. Текущее визуальное объединение `uploaded` и `processing` требует согласования с архитектором. Сам статус `uploaded` из кода и обработки ответов API не удалён.

### Загрузка файлов

Окно загрузки доступно из библиотеки документов и по кнопке прикрепления в чате.

- Можно выбрать несколько файлов одновременно.
- Повторное открытие системного выбора дополняет текущий список.
- До отправки можно убрать отдельные файлы из очереди.
- Выбор файлов сам по себе не начинает загрузку.
- Название и размер файла находятся в одной строке; размер расположен рядом с кнопкой удаления с отступом.
- Для длинного названия используется сокращение с многоточием.
- Причина ошибки отображается под названием и размером одной фразой.
- Окно расширено; отдельной прокрутки списка файлов нет. Длинное окно прокручивается без видимой полосы.

#### Клиентская проверка

Перед отправкой каждый файл проверяется на:

- расширение `.txt`;
- размер не более 10 МиБ — 10 485 760 байт;
- ненулевой размер.

Если хотя бы один файл не проходит проверку, отправка всей очереди блокируется. Неподходящий файл остаётся в списке с причиной ошибки. После удаления всех неподходящих файлов загрузка становится доступной.

Проверка действует как для кнопки, так и для обработчика отправки формы.

Клиентская проверка не заменяет серверную. Проверка кодировки и содержимого выполняется backend.

#### Отправка и обработка ошибок

Backend принимает один файл в одном запросе. Поэтому frontend отправляет очередь последовательно: отдельный `POST /documents` с multipart-полем `file` для каждого файла.

- На время отправки заблокированы повторный запуск, изменение списка и закрытие окна.
- При успешном принятии всех файлов окно закрывается.
- Принятие файла сервером не означает завершения обработки: дальнейший статус отслеживается через polling.
- Ошибка отдельного серверного запроса не останавливает отправку остальных файлов.
- При частичном успехе окно остаётся открытым и показывает результаты.
- Повторная попытка внутри текущего окна отправляет только файлы с ошибкой и новые файлы. Уже принятые файлы повторно не отправляются.
- Повторный выбор и загрузка того же файла в новой очереди разрешены.
- Файлы с одинаковыми именами не объединяются: документы различаются по ID.

Множественная загрузка не является атомарной операцией: часть запросов может завершиться успешно, а часть — ошибкой.

По умолчанию backend ограничивает библиотеку 100 документами и размер файла 10 МиБ. Серверные значения настраиваются на backend. Отдельный лимит количества файлов в одном выборе на frontend не вводится; превышение лимита библиотеки отображается как серверная ошибка.

### Область поиска в чате

- По умолчанию выбраны «Все документы».
- В режиме «Все» галочки у отдельных файлов не устанавливаются.
- Галочки обозначают только явный выбор конкретных документов.
- Снятие последней галочки возвращает режим «Все», не проставляя галочки остальным файлам.
- Пункт «Все» отделён от списка файлов разделителем.
- Под ним расположен поиск по названиям.
- Поиск не сбрасывает выбор файлов, скрытых фильтром.
- При повторном открытии списка строка поиска очищается.
- Для выбора доступны только документы со статусом `ready`.

В запросе к API:

- `document_ids: null` — поиск по всем готовым документам;
- массив ID — поиск по явно выбранным документам;
- пустой массив не отправляется.

Отправка вопроса недоступна, если в выбранной области нет готовых документов.

### Чат

- Название и выбор области поиска расположены внутри карточки чата.
- Пока загружается начальный список документов, отображается «Загружаем документы…».
- После загрузки списка приветствие зависит от наличия готовых документов.
- Пустой вопрос и вопрос из одних пробелов не отправляются.
- Длина вопроса ограничена 2000 символами.
- Enter отправляет вопрос, Shift + Enter добавляет перенос строки.
- Поле ввода растёт вверх с одной до двух строк.
- Ручное изменение размера поля отключено.
- Длинный текст прокручивается внутри поля без видимой полосы.
- Во время ожидания ответа повторная отправка заблокирована.
- Поддерживаются состояния ответа `answered`, `partial` и `insufficient_info`.
- Недостаток информации отделён от технической ошибки.
- Повтор после технической ошибки использует сохранённый вопрос и область поиска.

В интерфейсе показывается последняя пара «вопрос — ответ». История бесед не сохраняется.

### Источники

- Источники открываются кнопкой «Источники» в боковой панели справа.
- Название документа и цитата берутся из `Source.filename` и `Source.quote`.
- Frontend не восстанавливает цитату самостоятельно по `start_char` и `end_char`.

## API

Клиент использует следующие методы:

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/documents` | Получение списка документов |
| `GET` | `/documents/{id}` | Получение документа и проверка статуса |
| `POST` | `/documents` | Загрузка одного TXT-файла |
| `DELETE` | `/documents/{id}` | Удаление документа |
| `POST` | `/chat/ask` | Отправка вопроса с областью поиска |

Типы запросов и ответов находятся в `src/types/api.ts`.

## Оформление и иконки

- Базовые стили и цветовые переменные находятся в `src/index.css`.
- Стили компонентов находятся в `src/App.css`.
- Цвета статусов документов и отправленного сообщения выделены в отдельные переменные.
- Используются SVG-файлы Tabler Icons через общий компонент `Icon`.
- SVG находятся в `src/assets/icons/`.
- Иконки отображаются через CSS-маску; цвет задаётся через `currentColor`, размер — пропсом `size`.
- Доступное название кнопки задаётся её текстом или `aria-label`; декоративные иконки скрыты от скринридера.

Tabler Icons распространяются по лицензии MIT. Текст лицензии с уведомлением об авторских правах хранится в `licenses/tabler-icons-LICENSE.txt`.

## Проверенные вручную сценарии

При подключении к локальному backend проверены:

- получение списка документов;
- загрузка TXT и переход к готовому состоянию;
- отправка вопроса и просмотр источника;
- сохранение документа после обновления страницы;
- удаление документа;
- выбор нескольких файлов;
- блокировка всей очереди при наличии неподходящего файла;
- отправка подходящих файлов после удаления неподходящего;
- закрытие окна после успешной загрузки;
- отображение начального состояния загрузки списка в чате.

Проверка проводилась с серверным MockLLM. Работа с реальной языковой моделью и её качество требуют отдельной проверки.

## Ограничения текущего этапа

- Интерфейс рассчитан на компьютер; мобильная версия не реализована.
- Поддерживаются только TXT. PDF, DOCX, PPTX и OCR не входят в текущий этап.
- Drag-and-drop не реализован: используется системное окно выбора файлов.
- Нет папок, авторизации, настроек профиля и сохранённой истории чатов.
- Нет атомарной пакетной загрузки и автоматического устранения дубликатов.
- При потере ответа на запрос загрузки frontend не может гарантировать, что сервер не успел принять файл. Повторная попытка в таком случае потенциально создаёт отдельный документ.
- Строгая проверка структуры ответов API во время выполнения не добавлена.
- Inter указан в CSS, но локальные файлы шрифта пока не подключены. При отсутствии шрифта используется запасной.
- Объединённое отображение `uploaded` и `processing` требует согласования.
- Остаются 5 известных QA-падений.
- Production-маршрутизация API настраивается отдельно.
