# FinDocs Frontend

Фронтенд-приложение FinDocs (MVP-срез TXT) на React + TypeScript + Vite.
Десктопный интерфейс: библиотека документов, выбор материалов для поиска,
вопросы и ответы с источниками.

## Требования

- Node.js совместимой с Vite версии: рекомендуется Node.js 22.12+ или 24 LTS.
- npm (менеджер пакетов).

## Установка и запуск

1. Перейдите в папку `frontend`:

```bash
cd frontend
```

2. Установите зависимости:

```bash
npm install
```

3. Запустите dev-сервер:

```bash
npm run dev
```

4. Откройте адрес, указанный Vite в терминале. Обычно это `http://localhost:5173/`.

## Сборка и проверки

Перед коммитом выполняется следующий цикл:

```bash
npm run format    # Форматирование кода (Prettier)
npm run lint      # Проверка кода линтером (ESLint)
npm run build     # Проверка TypeScript и production-сборка Vite
npm test -- --run # Однократный запуск тестов (Vitest)
```

Для запуска тестов в режиме наблюдения используется `npm test`.

## Mock-режим и реальный API

- **Backend API (0.6) существует**, но интеграция с frontend пока не выполнена.
  Поэтому приложение работает в **mock-режиме**.
- **Включение/выключение mock-режима:** в файле `src/api/index.ts` через флаг `USE_MOCK`.
- **Адрес реального API:** задаётся через переменную окружения `VITE_API_BASE_URL`
  в файле `.env` (шаблон лежит в `.env.example`).

Mock API хранит данные в памяти страницы, имитирует задержки запросов и переходы
статусов документов. Ответы используют демонстрационные данные и фиксированный
источник: реальный поиск по содержимому загруженных файлов в этой заглушке не выполняется.

## Реализованные сценарии

### Документы

- Список файлов на всю доступную ширину, без папок.
- Поиск по названию без учёта регистра.
- Название, размер, статус, дата и время загрузки в строке документа.
- Статус расположен по центру строки; дата и время отображаются рядом.
- Удаление через меню с тремя точками и подтверждение действия.
- Раздельные состояния пустой библиотеки и отсутствия совпадений при поиске.
- Polling для промежуточных статусов; ошибка соединения и повтор проверки
  отображаются отдельно от статуса обработки документа.

Все четыре статуса API сохранены: `uploaded`, `processing`, `ready`, `error`.
В текущем интерфейсе `uploaded` и `processing` используют жёлтую плашку «Обработка»;
для `uploaded` при наведении есть пояснение об ожидании обработки.
`ready` отображается зелёным как «Готов», `error` — красным как «Ошибка» с причиной.

Контракт предусматривает отдельную подпись «Загружен» для `uploaded`.
Визуальное объединение с обработкой требует согласования с архитектором.

### Загрузка

- Одно окно загрузки для кнопки в документах и скрепки в чате.
- Клиентская проверка расширения `.txt`, размера до 10 МБ и ненулевого размера файла.
- Выбор файла не отправляет его автоматически: требуется нажать «Загрузить».
- Ошибки отображаются внутри окна; при сбое отправки выбранный файл сохраняется
  и доступна повторная попытка.
- После успешной отправки документ добавляется в список, а polling отслеживает обработку.

Клиентская проверка не заменяет серверную. Проверка кодировки UTF-8 и содержимого
относится к серверной обработке; в mock-режиме она не выполняется.

### Область поиска

- По умолчанию включён режим «Все документы» без галочек у отдельных файлов.
- Галочки обозначают только явно выбранные файлы.
- Снятие последней галочки автоматически возвращает режим «Все».
