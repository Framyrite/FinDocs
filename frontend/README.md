# FinDocs Frontend

Десктопный интерфейс FinDocs на React, TypeScript и Vite: библиотека TXT-документов, выбор материалов для поиска, вопросы и ответы с источниками.

## Требования

- Node.js 22.12+ или совместимая актуальная LTS-версия.
- npm.
- Запущенный backend для работы с реальным API.

Подготовка backend описана в [backend/README.md](../backend/README.md).

## Установка и запуск

Из корня репозитория:

```powershell
cd frontend
npm ci
```

Если локального `.env` ещё нет:

```powershell
Copy-Item .env.example .env
```

Для локальной работы с backend:

```dotenv
VITE_USE_MOCK=false
VITE_API_BASE_URL=/api
```

Запустите backend согласно его README, затем в отдельном терминале из папки `frontend`:

```powershell
npm run dev
```

Откройте адрес из терминала Vite, обычно:

```text
http://localhost:5173/
```

Оба сервера должны оставаться запущенными.

После изменения `.env` необходимо перезапустить Vite. Личный `.env` не добавляется в Git; шаблон настроек находится в `.env.example`.

## Конфигурация API

Настройки читаются в `src/api/config.ts`. Для переключения режима не нужно редактировать исходники.

| Переменная | Поведение |
| --- | --- |
| `VITE_USE_MOCK=true` | Frontend mock без HTTP-запросов к backend |
| `VITE_USE_MOCK=false` или переменная отсутствует | Реальные HTTP-запросы |
| `VITE_API_BASE_URL` | Базовый адрес или путь API |

Mock включается только строковым значением `true`.

### Локальный API

В режиме разработки при отсутствующем или пустом адресе используется `/api`.

Vite dev proxy передаёт запросы на `http://127.0.0.1:8000`, удаляя префикс:

```text
/api/documents → http://127.0.0.1:8000/documents
```

Для проверки откройте:

```text
http://localhost:5173/api/documents
```

Ожидается JSON с полями `items` и `total`. Если Vite использует другой порт, измените его в адресе.

Прокси локальный и не требует VPN. Доступность внешних сервисов, если они отдельно используются backend, определяется его конфигурацией.

### Production

`VITE_API_BASE_URL` необходимо задать при сборке. При отсутствии адреса запрос отклоняется с сообщением о неверной конфигурации до вызова `fetch`.

Для значения `/api` маршрутизацию к backend нужно настроить на сервере развёртывания. Vite dev proxy работает только при `npm run dev`.

При прямом обращении браузера к другому origin необходима соответствующая настройка CORS на backend.

Переменные `VITE_*` включаются в клиентскую сборку: секреты в них не размещаются. После изменения переменных production-сборку нужно выполнить заново.

### Frontend mock и серверный MockLLM

Frontend mock:

- хранит данные в памяти страницы;
- имитирует задержки и статусы;
- использует демонстрационные ответы и источники;
- не выполняет реальный поиск по содержимому загруженных файлов;
- сбрасывает данные после обновления страницы.

`FINDOCS_LLM_PROVIDER=mock` — отдельная настройка backend. Она выбирает серверный MockLLM и не включает frontend mock.

В проверенном локальном сценарии frontend использует реальные HTTP-запросы, а backend — серверный MockLLM. Загрузка, хранение, обработка и поиск документов выполняются backend.

## Документы

- Библиотека занимает доступную ширину, без папок.
- Есть поиск по названию без учёта регистра.
- Удаление выполняется через меню документа с подтверждением.
- Отображаются название, размер, статус, дата и время загрузки.
- Статус расположен по центру строки; дата и время находятся рядом.
- Промежуточные статусы обновляются через polling.
- Ошибка polling и повтор проверки отделены от ошибки обработки документа.
- Начальная загрузка, ошибка получения списка, пустая библиотека и отсутствие совпадений при поиске — разные состояния.
- При ошибке получения списка показывается сообщение с кнопкой «Повторить».
- Во время повтора отображается загрузка; успешный ответ возвращает обычный интерфейс.

### Статусы

Все четыре статуса API сохранены в коде:

| API | Отображение |
| --- | --- |
| `uploaded` | Жёлтая плашка «Обработка», пояснение об ожидании обработки при наведении |
| `processing` | Жёлтая плашка «Обработка» |
| `ready` | Зелёная плашка «Готов» |
| `error` | Красная плашка «Ошибка» с причиной |

Объединённое отображение `uploaded` и `processing` согласовано.

Это только представление в интерфейсе: принятие файла и обработка остаются разными состояниями API.

### Удаление и синхронизация

При успешном удалении документ исключается из библиотеки, явного выбора и ошибок polling.

Если DELETE вернул 404:

- отсутствующий документ исключается из локального состояния;
- библиотека повторно загружается с сервера;
- выбранные ID и ошибки polling сверяются с актуальным списком;
- пользователь получает сообщение, что документа уже нет, без утверждения об успешном DELETE.

Если обновление списка после 404 не удалось, известный отсутствующий файл всё равно убирается. Остальные данные сохраняются, показывается отдельное сообщение о сбое обновления.

При сетевой ошибке или другом неуспешном ответе DELETE документ и его выбор сохраняются.

## Множественная загрузка

Окно доступно из библиотеки и по кнопке прикрепления в чате.

### Выбор и проверка файлов

- Можно выбрать несколько файлов и дополнить очередь повторным выбором.
- Выбор сам по себе не запускает отправку.
- До отправки отдельные файлы можно убрать из очереди.
- Каждый файл проверяется на расширение `.txt`, ненулевой размер и ограничение 10 МиБ — 10 485 760 байт.
- Любой неподходящий файл блокирует всю очередь до его удаления.
- Проверка действует и в обработчике формы, а не только через недоступность кнопки.
- Название и размер расположены в одной строке, причина ошибки — ниже одной фразой.
- Длинное название сокращается многоточием.
- Список не имеет отдельной прокрутки. Длинное окно прокручивается без видимой полосы.

### Отправка

- Файлы отправляются последовательно, отдельными `POST /documents` с multipart-полем `file`.
- На время отправки блокируются повторный запуск, изменение очереди и закрытие окна.
- При успешном принятии всех файлов окно закрывается.
- Обработка продолжается на backend, статусы обновляет polling.
- Ошибка отдельного серверного запроса не останавливает остальные.
- При частичном успехе окно остаётся открытым с результатами.
- Повтор внутри текущего окна отправляет только файлы с ошибкой и новые файлы.
- Уже принятые файлы повторно не отправляются.
- Повторный выбор того же файла в новой очереди разрешён.
- Имена файлов не используются для устранения дубликатов.

По умолчанию backend ограничивает библиотеку 100 документами и размер файла 10 МиБ. Серверные значения настраиваются на backend.

Отдельный лимит количества файлов в одном выборе на frontend не введён.

Клиентская проверка не заменяет серверную проверку кодировки и содержимого.

Множественная загрузка не атомарна. Если ответ на POST потерялся после принятия файла сервером, повтор потенциально может создать отдельный документ: идемпотентность не реализована.

## Область поиска

- Изначально включены «Все готовые документы», без галочек у отдельных файлов.
- Галочки обозначают явный выбор документов.
- Для выбора доступны только файлы со статусом `ready`.
- После снятия последней галочки остаётся пустой выбор. Автоматического перехода на «Все» нет.
- Удаление последнего выбранного документа тоже оставляет пустой выбор.
- Остальные выбранные документы сохраняются, если они существуют.
- При пустом выборе показывается подсказка, ввод и отправка вопроса блокируются.
- В режим «Все» пользователь возвращается только отдельной кнопкой.
- Поиск по названиям не меняет выбор скрытых файлов.
- При повторном открытии списка строка поиска очищается.
- Пункт «Все» и поиск остаются над прокручиваемым списком файлов.

В состоянии frontend:

| Значение | Значение выбора |
| --- | --- |
| `null` | Все готовые документы |
| `[]` | Пустой выбор |
| Непустой массив ID | Конкретные документы |

В API отправляются только `document_ids: null` или непустой массив ID. Пустой массив не отправляется.

Выбор сохраняется при переключении разделов приложения. После обновления страницы начальным режимом снова является «Все».

## Чат и источники

- Название и выбор области поиска расположены внутри карточки чата.
- Во время первоначальной загрузки списка отображается «Загружаем документы…».
- При ошибке загрузки показываются причина и кнопка «Повторить»; вопрос отправить нельзя.
- Пустой вопрос и вопрос из пробелов не отправляются.
- Ограничение длины вопроса — 2000 символов.
- Enter отправляет вопрос, Shift + Enter добавляет перенос строки.
- Поле ввода растёт вверх с одной до двух строк, без ручного изменения размера.
- Длинный текст прокручивается без видимой полосы.
- Поле очищается сразу при отправке; вопрос остаётся в переписке во время ожидания ответа.
- Во время ожидания повторная отправка заблокирована.
- Поддерживаются ответы `answered`, `partial` и `insufficient_info`.
- Техническая ошибка отделена от недостатка информации.
- При ошибке текст вопроса восстанавливается в поле. Можно исправить его или повторить исходный запрос с исходной областью поиска.
- Источники открываются кнопкой «Источники» в правой боковой панели.
- Название и цитата берутся из `Source.filename` и `Source.quote`.
- Frontend не вырезает цитату по индексам `start_char` и `end_char`.

Показывается последняя пара «вопрос — ответ», без истории бесед.

Локальные вопрос и ответ сбрасываются при уходе с вкладки чата или обновлении страницы.

## Обработка ответов API

Клиент различает:

- сетевой сбой без HTTP-ответа;
- HTTP-ошибку с сохранением кода, включая 404;
- некорректный успешный ответ: неожиданный Content-Type, повреждённый JSON или значение вместо объекта верхнего уровня.

При HTTP-ошибке используется корректное сообщение backend либо сообщение с HTTP-кодом.

HTML и повреждённое тело ошибки не приводят к потере HTTP-кода. Ответ 204 без тела остаётся корректным результатом удаления.

В успешных JSON-ответах проверяются формат и объект верхнего уровня. Полная runtime-валидация полей и вложенных структур не реализована.

### Используемые методы

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/documents` | Список документов |
| GET | `/documents/{id}` | Документ и статус для polling |
| POST | `/documents` | Загрузка одного файла |
| DELETE | `/documents/{id}` | Удаление |
| POST | `/chat/ask` | Вопрос с областью поиска |

Типы находятся в `src/types/api.ts` и опираются на `mvp-contracts.md` v0.2.

## Оформление и иконки

- Базовые стили и цветовые переменные: `src/index.css`.
- Оформление компонентов: `src/App.css`.
- Цвета статусов и отправленного сообщения выделены в отдельные переменные.
- SVG Tabler Icons находятся в `src/assets/icons/`.

- Доступное название задаёт текст или `aria-label` кнопки.
- Tabler Icons распространяются по MIT. Лицензия: `licenses/tabler-icons-LICENSE.txt`.

Из папки `frontend`:

```powershell

npm run lint
npm run build
npm test -- --run
```

Чтобы форматировать только изменённые файлы, используйте `npx prettier --write` с их путями.

Общая команда `format` также форматирует QA-файлы. Такие изменения следует проверять перед коммитом.

Дополнительные команды:

```powershell

# Интеграционные проверки App
```

### Ручные проверки

С локальным backend и серверным MockLLM проверены:

- получение списка документов;
- загрузка и переход к статусу `ready`;
- вопрос, ответ и источник;
- сохранение документа после обновления страницы;
- удаление;
- блокировка некорректной очереди загрузки;
- пустой выбор и ручное возвращение к режиму «Все»;
- удаление с 404 в двух вкладках;
- восстановление списка кнопкой «Повторить» после недоступности backend;
- очистка поля сразу после отправки вопроса.

Дополнительно проведён ручной просмотр прокручиваемых областей по чек-листу для уменьшенной высоты окна и навигации с клавиатуры.

## Ограничения

- Только десктоп и TXT.
- Нет мобильной версии, PDF/DOCX/PPTX, OCR и drag-and-drop.
- Нет папок, авторизации, настроек профиля и сохранённой истории чатов.
- Нет атомарной пакетной загрузки, идемпотентности и устранения дубликатов.
- Нет полной runtime-валидации полей API.
- Inter указан в CSS, но локальные файлы шрифта не подключены. При отсутствии используется запасной шрифт.
- Production-маршрутизация и работа с реальной языковой моделью требуют отдельной проверки.
- Остаются пять QA-падений, перечисленных выше.
