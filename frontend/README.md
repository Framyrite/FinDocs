# FinDocs Frontend

Десктопный интерфейс FinDocs на React, TypeScript и Vite: библиотека TXT-документов, выбор материалов для поиска, вопросы и ответы с источниками.

## Требования и запуск

- Node.js 22.12+ или совместимая актуальная LTS-версия.
- npm.
- Запущенный backend для работы с реальным API. Его подготовка описана в [backend/README.md](../backend/README.md).

Из корня репозитория:

```powershell
cd frontend
npm ci
```

Если локального `.env` ещё нет:

```powershell
Copy-Item .env.example .env
```

Для локальной работы с backend:

```dotenv
VITE_USE_MOCK=false
VITE_API_BASE_URL=/api
```

Запустите backend согласно его README, затем в отдельном терминале из `frontend`:

```powershell
npm run dev
```

Откройте адрес из терминала Vite, обычно `http://localhost:5173/`. Оба сервера должны оставаться запущенными.

После изменения `.env` необходимо перезапустить Vite. Личный `.env` не добавляется в Git; шаблон настроек находится в `.env.example`.

## Конфигурация API

Настройки читаются в `src/api/config.ts`; редактировать исходники для переключения режима не нужно.

| Переменная                                       | Поведение                                 |
| ------------------------------------------------ | ----------------------------------------- |
| `VITE_USE_MOCK=true`                             | Frontend mock без HTTP-запросов к backend |
| `VITE_USE_MOCK=false` или переменная отсутствует | Реальные HTTP-запросы                     |
| `VITE_API_BASE_URL`                              | Базовый адрес или путь API                |

Mock включается только строковым значением `true`.

### Локальный API

В режиме разработки при отсутствующем или пустом адресе используется `/api`. Vite dev proxy передаёт запросы на `http://127.0.0.1:8000`, удаляя префикс:

```text
/api/documents → http://127.0.0.1:8000/documents
```

Для проверки откройте `http://localhost:5173/api/documents`: ожидается JSON с `items` и `total`. Если Vite использует другой порт, измените его в адресе.

Прокси локальный и не требует VPN. Доступность внешних сервисов, если они отдельно используются backend, определяется его конфигурацией.

### Production

`VITE_API_BASE_URL` необходимо задать при сборке. При отсутствии адреса запрос отклоняется с сообщением о неверной конфигурации до вызова `fetch`.

Для значения `/api` маршрутизацию к backend нужно настроить на сервере развёртывания. Vite dev proxy работает только при `npm run dev`. При прямом обращении браузера к другому origin необходима соответствующая настройка CORS на backend.

Переменные `VITE_*` включаются в клиентскую сборку: секреты в них не размещаются. После их изменения production-сборку нужно выполнить заново.

### Frontend mock и серверный MockLLM

Frontend mock хранит данные в памяти страницы, имитирует задержки и статусы, использует демонстрационные ответы и источники. Реального поиска по содержимому загруженных файлов в нём нет; после обновления страницы данные сбрасываются.

`FINDOCS_LLM_PROVIDER=mock` — отдельная настройка backend. Она выбирает серверный MockLLM и не включает frontend mock. В проверенном локальном сценарии frontend использует реальные HTTP-запросы, а backend — серверный MockLLM; загрузка, хранение, обработка и поиск документов выполняются backend.

## Документы

- Библиотека занимает доступную ширину, без папок.
- Есть поиск по названию без учёта регистра и удаление с подтверждением.
- Отображаются название, размер, статус, дата и время загрузки.
- Статус расположен по центру строки; дата и время находятся рядом.
- Промежуточные статусы обновляются через polling.
- Ошибка polling и повтор проверки отделены от ошибки обработки документа.
- Начальная загрузка, ошибка получения списка, пустая библиотека и отсутствие совпадений при поиске — разные состояния.
- При ошибке получения списка показывается сообщение с кнопкой «Повторить». Во время повтора отображается загрузка; успешный ответ возвращает обычный интерфейс.
