# Журнал архитектурных решений FinDocs

## Для чего нужен этот файл

`decisions.md` — это краткий журнал важных технических и архитектурных решений проекта.

Он нужен, чтобы команда понимала:

- какие решения были приняты;
- почему мы выбрали именно такой вариант;
- что изменилось со временем;
- какие решения считаются актуальными;
- почему сейчас не стоит возвращаться к уже обсуждённым вариантам без новых оснований.

Это **не документация всей архитектуры**.  
Текущее устройство системы описывается в `architecture.md`, а причины ключевых решений и история их изменения — здесь.

## Легенда

### Нумерация решений

Каждое решение получает уникальный номер:

`ADR-001`, `ADR-002`, `ADR-003` ...

Номер после создания не меняется и не переиспользуется.

### Статусы

Используем минимальный набор:

- **Принято** — решение действует сейчас.
- **Изменено** — решение было пересмотрено и заменено другим.
- **Отменено** — решение больше не применяется.
- **На обсуждении** — решение ещё не принято.

### Версии

Отдельные версии для каждого ADR не нужны.

Версия фиксируется на уровне самого файла через историю Git.

Если решение меняется существенно, не переписываем историю молча:
1. меняем статус старого решения на `Изменено`;
2. указываем, каким решением оно заменено;
3. создаём новый ADR с новым номером.

### Как отмечать изменения

Для небольших правок внутри решения достаточно обычного коммита Git.

Если меняется **само архитектурное решение**, запись не переписываем задним числом. Вместо этого добавляем новый ADR.

Пример:

```text
ADR-003 — PostgreSQL + pgvector
Статус: Изменено
Заменено: ADR-008
```

А в новом решении:

```text
ADR-008 — Другое решение для хранения векторов
Статус: Принято
Заменяет: ADR-003
```
