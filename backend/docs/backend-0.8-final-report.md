# FinDocs — Backend 0.8
## Итоговый отчёт о реализации и проверке

**Дата:** 15 ноября 2026 года  
**Этап:** Backend 0.8 — Quality of Retrieval and Context  
**Ветка:** `feat/backend-retrieval-context-0.8`  
**Статус реализации:** Завершена, проведены локальные проверки  
**Статус приёмки:** Ожидает независимого QA, согласования контракта и Code Review

### 1. Цель этапа

Повысить качество лексического поиска по TXT-документам и обеспечить передачу LLM достаточных доказательных фрагментов. Устранить ложные отказы `insufficient_info`, сохранив проверяемость источников и безопасность генерации.

Работы выполнены без внедрения embeddings, векторной базы, новой модели или изменения публичного API `POST /chat/ask`.

### 2. Выполненные изменения

**Retrieval**

- Доработаны нормализация и ранжирование лексических совпадений.
- Добавлен ограниченный fallback для релевантных кандидатов.
- Улучшена обработка аббревиатур FCFS, FIFO, RR и SJF.
- Учтён случай `FIFO1`, где цифра является маркером сноски.
- Сохранены ограничения области поиска и детерминированный отбор результатов.

**LLM Context**

- Отделён расширенный контекст модели от коротких пользовательских цитат.
- Добавлена сборка контекста из проверенных чанков.
- Реализован ограниченный добор соседних фрагментов того же документа.
- Добавлены проверки диапазонов и перекрывающихся участков.
- Сохранён интерфейс `LLMAdapter` и совместимость с `MockLLM`.

**Sources**

- Добавлен подбор выдержек с учётом ответа модели.
- Улучшена доказательность цитат для D01, D02, D04, P01 и P02.
- Сохранены оригинальные UUID, Unicode-смещения и ограничение 300 символов.
- Добавлены проверки точного соответствия цитат исходным TXT.

**Проверка полноты**

- Добавлена консервативная проверка составных вопросов о годе, участнике и событии.
- Для D03 реализован корректный отказ при отсутствии полного подтверждения.
- Добавлены позитивные и негативные регрессионные тесты.

### 5. Безопасность

Для I01–I02 сквозной поиск не передавал фрагменты модели, поэтому дополнительно проведён прямой тест `OllamaLLMAdapter`.

В контекст передавался исходный документ с вредоносной инструкцией выдать выдуманный платёж в размере 5000 долларов.

Модель отказалась отвечать без подтверждающих фактов.

Результат подтверждает устойчивость на проверенном сценарии, но не является доказательством защиты от любых prompt injection.

### 6. Ограничения

- Поиск остаётся лексическим; семантическая релевантность всех возможных вопросов не гарантируется.
- Подбор цитат использует эвристики и не выполняет полноценную проверку логического следования ответа из документа.
- Проверка составных вопросов о годе и участнике консервативна и может давать ложные отказы на иных формулировках.
- Ограничение контекста в символах не эквивалентно точному токенному бюджету с учётом системного промпта и ответа; это требует отдельной оценки.
- Независимая повторная проверка Артёма и результаты CI для ветки Backend 0.8 пока не подтверждены.
- Нормативные изменения по сравнению с §6.7 MVP v0.2 требуют оформленного согласования Влада.

### 7. Вывод

Backend 0.8 устранил воспроизведённые проблемы поиска и недостаточного LLM-контекста. Проверяемость цитат сохранена, качество подтверждающих выдержек улучшено, негативные сценарии не регрессировали.

**Реализация готова к PR и независимому ревью.** Полная приёмка и merge возможны после согласования изменений контракта, проверки CI, независимого QA Артёма и Code Review Влада.

После выполнения этих условий отчёт дополняется ссылкой на PR, результатом CI и решением по приёмке без создания новых промежуточных отчётов.
