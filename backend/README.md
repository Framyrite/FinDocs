
# FinDocs Backend

Серверная часть FinDocs на Python 3.12 и FastAPI.

Backend 0.5 реализует локальную библиотеку TXT-документов: загрузку через HTTP, сохранение файлов, фоновую обработку, получение статусов, фильтрацию и удаление.

## Реализованные компоненты

- `GET /health` — проверка доступности приложения.
- `POST /documents` — загрузка TXT-файла.
- `GET /documents` — список документов с поиском и фильтрацией.
- `GET /documents/{document_id}` — получение документа и его статуса.
- `DELETE /documents/{document_id}` — физическое удаление документа.
- `app/documents/` — модели, файловое хранилище и управление обработкой.
- `app/processing/` — обработка TXT, создание блоков и чанков.
- `Settings` — конфигурация через переменные окружения и `.env`.
- `LLMAdapter` и `MockLLM` — интерфейс и тестовая реализация LLM.

Поддерживаются TXT-файлы в кодировке UTF-8, включая UTF-8 BOM.

PostgreSQL, RAG, embeddings, настоящая LLM, `/chat/ask`, PDF и DOCX не входят в Backend 0.5.

## Требования

- Python 3.12.
- Доступ к PyPI при первоначальной установке зависимостей.
- Токенизатор `multilingual-e5-small` для обработки TXT.
- Один процесс Uvicorn для работы с локальным файловым хранилищем.

## Установка

Рекомендуется создавать виртуальное окружение в корне репозитория.

### Linux / macOS

Из корня FinDocs:

```bash
python3.12 -m venv .venv
source .venv/bin/activate

cd backend
python -m pip install -r requirements-dev.txt
```

Если `.venv` уже существует, повторно создавать его не нужно:

```bash
cd ~/Projects/FinDocs
source .venv/bin/activate
cd backend
```

### Windows PowerShell

Из корня репозитория:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1

cd backend
python -m pip install -r requirements-dev.txt
```

### Зависимости

- `requirements.txt` — зависимости приложения.
- `requirements-dev.txt` — зависимости приложения, pytest, httpx и Ruff.
- `python-multipart` — обработка загрузок `multipart/form-data`.

Проверка установленных зависимостей:

```bash
python -m pip check
```

## Конфигурация

Настройки читаются из переменных окружения и файла `backend/.env`.

При необходимости создайте `.env` из примера:

```bash
cp .env.example .env
```

Не перезаписывайте существующий `.env`, если в нём уже есть локальные настройки.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `FINDOCS_APP_NAME` | `FinDocs Backend` | Название приложения |
| `FINDOCS_DEBUG` | `false` | Режим отладки |
| `FINDOCS_DATA_DIR` | `backend/data/` | Корневой каталог хранения документов |
| `FINDOCS_MAX_TXT_SIZE_MB` | `10` | Максимальный размер TXT в МиБ |
| `FINDOCS_MAX_DOCUMENTS` | `100` | Максимальное количество документов |
| `FINDOCS_TOKENIZER_DIR` | Путь внутри `backend/models/` | Необязательное переопределение каталога токенизатора |

Приоритет конфигурации:

1. Переменные окружения процесса.
2. Файл `backend/.env`.
3. Значения по умолчанию.

Каталог `backend/data/` по умолчанию определяется относительно самого backend, а не текущей директории терминала.

Для `FINDOCS_DATA_DIR` рекомендуется использовать абсолютный путь, если требуется другое расположение хранилища.

Настройки валидируются через Pydantic. Лимиты размера и количества документов должны быть положительными целыми числами.

После изменения настроек запущенный сервер необходимо перезапустить.

## Установка токенизатора

TXT-обработка использует токенизатор `multilingual-e5-small`.

Файл `tokenizer.json` не хранится в Git и не загружается автоматически при запуске приложения.

Из каталога `backend`:

```bash
mkdir -p models/multilingual-e5-small

curl -fL --retry 3 \
  "https://huggingface.co/intfloat/multilingual-e5-small/resolve/ada7b62be30f82b0bc5da131b0477721c8fc14e9/tokenizer.json" \
  -o models/multilingual-e5-small/tokenizer.json
```

Проверка SHA-256 на Linux / macOS:

```bash
echo "0b44a9d7b51c3c62626640cda0e2c2f70fdacdc25bbbd68038369d14ebdf4c39  models/multilingual-e5-small/tokenizer.json" \
  | shasum -a 256 -c -
```

Ожидаемый результат:

```text
models/multilingual-e5-small/tokenizer.json: OK
```

Используется `tokenizers==0.23.3`.

Из каталога `backend` с активированным виртуальным окружением:

```bash
python -m uvicorn app.main:app \
  --host 127.0.0.1 \
  --port 8000 \
  --reload
```

Остановка сервера — `Ctrl+C`.

Интерактивная документация FastAPI:

- http://127.0.0.1:8000/docs
- http://127.0.0.1:8000/openapi.json

Проверка доступности:

```bash
curl -i http://127.0.0.1:8000/health
```

Ожидаемый результат:

```json
{
  "status": "ok"
}
```

`GET /health` проверяет доступность HTTP-приложения, а не наличие базы данных, RAG или реальной LLM.

## Локальное хранение документов

Документы сохраняются на диске в каталоге, указанном через `FINDOCS_DATA_DIR`.

Структура по умолчанию:

```text
backend/
└── data/
    └── documents/
        └── <uuid>/
            ├── original.bin
            ├── meta.json
            └── result.json
```

Назначение файлов:

- `original.bin` — исходные байты TXT без изменений.
- `meta.json` — метаданные и текущий статус документа.
- `result.json` — результат успешной обработки: блоки и чанки.

`result.json` появляется после успешной обработки.

Каждый документ идентифицируется UUID, поэтому одинаковые имена файлов разрешены.

Изменение метаданных и сохранение файлов выполняются с использованием атомарной записи.

Каталог `backend/data/` исключён из Git.

### Состояния документа

| Статус | Значение |
| --- | --- |
| `uploaded` | Файл принят и сохранён |
| `processing` | Выполняется TXT-обработка |
| `ready` | Обработка успешно завершена |
| `error` | Во время обработки произошла ошибка |

Переходы статусов:

```text
uploaded → processing → ready
                      ↘ error
```

У документа со статусом `error` заполнены `error_code` и `error_message`.

У документа со статусом `ready` оба поля ошибки равны `null`.

## HTTP API документов

### POST /documents — загрузка

Эндпоинт принимает `multipart/form-data` с одним полем `file`.

Для ручной проверки сначала создайте файл:

```bash
printf 'Привет, FinDocs!\n' > example.txt
```

Загрузите его:

```bash
curl -i \
  -F "file=@example.txt;type=text/plain" \
  http://127.0.0.1:8000/documents
```

Успешный ответ — `202 Accepted`.

Пример ответа:

```json
{
  "id": "12345678-1234-5678-1234-567812345678",
  "filename": "example.txt",
  "format": "txt",
  "status": "uploaded",
  "error_code": null,
  "error_message": null,
  "size_bytes": 17,
  "created_at": "2026-11-05T12:00:00Z"
}
```

Пример приведён для иллюстрации структуры. Реальные UUID, дата и размер зависят от загруженного файла.

После сохранения документа запускается фоновая задача через FastAPI `BackgroundTasks`.

Фоновая задача получает UUID, читает сохранённый `original.bin`, вызывает `process_txt()` и записывает результат или ошибку обработки.

Неверная UTF-8 кодировка и TXT из одних пробелов могут пройти HTTP-загрузку, но затем получить статус `error`.

### GET /documents — список

Получить все документы:

```bash
curl http://127.0.0.1:8000/documents
```

Формат ответа:

```json
{
  "items": [],
  "total": 0
}
```

`items` содержит документы, а `total` — количество элементов после применения фильтров.

Документы сортируются по времени создания: новые первыми.

Доступны необязательные параметры:

- `status` — `uploaded`, `processing`, `ready` или `error`.
- `q` — подстрока имени файла без учёта регистра.

Пример:

```bash
curl "http://127.0.0.1:8000/documents?status=ready&q=example"
```

Постраничная выдача в Backend 0.5 не реализована.

### GET /documents/{document_id} — получение документа

```bash
curl http://127.0.0.1:8000/documents/<document_id>
```

Замените `<document_id>` на UUID из ответа `POST /documents`.

Успешный ответ — `200 OK` с актуальными метаданными документа.

Если документ не найден, возвращается `404` с кодом `document_not_found`.

Этот маршрут предназначен в том числе для polling: frontend периодически проверяет статус, пока он не станет `ready` или `error`.

### DELETE /documents/{document_id} — удаление

```bash
curl -i -X DELETE \
  http://127.0.0.1:8000/documents/<document_id>
```

Успешный ответ — `204 No Content` без тела.

При удалении физически удаляется каталог документа со всеми его файлами.

После удаления документ:

- не появляется в `GET /documents`;
- не доступен через `GET /documents/{document_id}`;
- не восстанавливается после завершения ранее запущенной фоновой обработки.

Повторное удаление возвращает `404 document_not_found`.

## Ограничения и ошибки

Значения по умолчанию:

- Максимальный размер TXT — 10 МиБ.
- Максимум документов в библиотеке — 100.
- Нулевой файл запрещён.
- Поддерживаются только TXT-файлы.

Размер загрузки проверяется ограниченным чтением, без загрузки произвольно большого файла целиком.

Ограничение количества документов проверяется при создании под блокировкой репозитория.

### Ограничение размера HTTP-загрузки

При загрузке используется `UploadFile` и ограниченное чтение:

`file.read(max_bytes + 1)`

При стандартном лимите 10 МиБ приложение читает в память не более 10 МиБ + 1 байт содержимого файла. Дополнительный байт нужен для определения превышения лимита.

FastAPI/Starlette может временно сохранять multipart-загрузки на диск до выполнения обработчика. Поэтому текущая проверка ограничивает чтение файла приложением, но не является полным ограничением размера входящего HTTP-запроса.

Для публичного развёртывания необходим дополнительный лимит размера HTTP-запроса на уровне принимающего сервера или reverse proxy.

Отклонённый файл не создаёт документ в библиотеке.

### HTTP-ошибки

| HTTP | Код | Описание |
| --- | --- | --- |
| 415 | `unsupported_format` | Неподдерживаемый формат |
| 413 | `file_too_large` | Превышен лимит размера |
| 422 | `empty_file` | Файл нулевого размера |
| 409 | `document_limit_reached` | Достигнут лимит документов |
| 404 | `document_not_found` | Документ не найден |

Формат ошибки соответствует контракту MVP v0.2:

```json
{
  "error": {
    "code": "file_too_large",
    "message": "Файл больше допустимого размера (10 МБ).",
    "details": {
      "max_size_mb": 10
    }
  }
}
```

Поля `code` и `message` обязательны, `details` — необязательное.

При некорректных параметрах запроса FastAPI возвращает HTTP `422` в общем формате ошибки. Для стандартных ошибок HTTP-валидации (некорректный UUID, отсутствующее поле file, недопустимый статус) используется код validation_error и HTTP 422.

### Ошибки фоновой обработки

Уже загруженный документ не получает HTTP-ошибку задним числом.

Вместо этого обновляются `status`, `error_code` и `error_message`.

| Код | Причина |
| --- | --- |
| `invalid_encoding` | TXT не декодируется как UTF-8 |
| `empty_document` | После декодирования нет содержательного текста |
| `processing_failed` | Другая ошибка обработки или прерванная обработка |

## Восстановление после перезапуска

При запуске FastAPI через `lifespan` вызывается `recover_incomplete()`.

Правила восстановления:

- `uploaded` → `error`.
- `processing` → `error`.
- `ready` остаётся `ready`.
- `error` остаётся `error`.
- Незавершённые каталоги без `meta.json` удаляются.

Для прерванной обработки используется код `processing_failed`.

Конструктор репозитория не выполняет восстановление автоматически: оно запускается при старте приложения.

### Потоки и удаление

Для синхронизации файлового репозитория используется `threading.RLock`.

Блокировка защищает создание, изменение статусов, завершение обработки, удаление и восстановление.

Во время выполнения `process_txt()` блокировка не удерживается.

Если документ удалён во время обработки, последующее сохранение результата не должно создавать его заново.

Backend 0.5 рассчитан на один процесс Uvicorn. Межпроцессная синхронизация и несколько worker-процессов не поддерживаются.

## Обработка TXT

Модуль `app/processing/` реализует:

- Декодирование UTF-8 и UTF-8 BOM.
- Проверку пустого содержимого и некорректной кодировки.
- Сохранение пробелов и переносов строк.
- Создание блоков документа.
- Разбиение текста на чанки по 350 токенов с перекрытием 50 токенов.
- Сохранение точных символьных диапазонов.
- Детерминированные UUID5 для блоков и чанков.

Пример прямого вызова:

```python
from uuid import uuid4

from app.processing import process_txt

result = process_txt(
    "Привет, FinDocs!".encode("utf-8"),
    uuid4(),
)

print(result.blocks)
print(result.chunks)
```

`process_txt()` обрабатывает данные в памяти.

Сохранение оригиналов, метаданных и результатов выполняется через `DocumentRepository`.

Модуль не создаёт embeddings и не выполняет RAG.

## LLM-адаптер

В проекте сохранён интерфейс:

```python
LLMAdapter.generate(question: str, context: str) -> str
```

`MockLLM` предоставляет детерминированную тестовую реализацию.

Он не выполняет поиск по документам, RAG или настоящую генерацию ответов.

Ручная проверка:

```bash
python -c "from app.main import app; print(app.state.llm_adapter.generate('Что такое FinDocs?', 'Тестовый контекст'))"
```

Фабрика `create_app()` поддерживает внедрение зависимостей:

```python
create_app(
    settings=...,
    llm_adapter=...,
    document_repository=...,
)
```

Это позволяет изолировать HTTP-тесты и использовать временные каталоги.

## Интеграция с frontend

Для локальной разработки с React/Vite выбран подход **Vite dev proxy**.

Frontend отправляет API-запросы через прокси Vite, который перенаправляет их на FastAPI по адресу `http://127.0.0.1:8000`.

Конкретная конфигурация proxy находится на стороне frontend.

Пример сценария взаимодействия:

1. Пользователь выбирает TXT.
2. Frontend вызывает `POST /documents`.
3. Backend сохраняет файл и возвращает `202`.
4. Frontend опрашивает `GET /documents/{document_id}`.
5. При статусе `ready` документ считается обработанным.
6. Список обновляется через `GET /documents`.
7. Удаление выполняется через `DELETE /documents/{document_id}`.

Vite dev proxy предназначен для локальной разработки и не заменяет настройку сетевого взаимодействия при развёртывании.
