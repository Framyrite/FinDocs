# Backend 0.8.2 — проект уточнения правил лексического поиска

Статус: **предложение алгоритма для проверки и согласования с Владом**; не заменяет утверждённый `mvp-contracts.md` v0.2 до review. Основа: baseline Backend 0.8.1 на 12 QA-вопросах и текущая реализация Backend 0.7.

## Изменения относительно MVP v0.2 (раздел 6.7)

1. Базовая нормализация `normalize_stems` и пятисимвольные основы остаются прежними. На этапе построения запроса исключаются общеязыковые вопросные термы `был`, `были`, `было`, `каком`, `кем`, `году`.
2. Двух- и более буквенные латинские аббревиатуры в верхнем регистре (например, `RR`, `FCFS`, `FIFO`) сохраняются для поиска. Римские цифры аббревиатурами не считаются.
3. Основной проход: прежний `coverage >= 0.6` для `Q`, уточнённого п. 1–2; прежние границы `ready` и scope. Выбирается не более `TOP_K=3`.
4. Резервный проход: `coverage >= 0.5`, не менее трёх **различных** совпавших термов; он используется только когда нет строгих кандидатов либо строгая выдача теряет явно указанную латинскую аббревиатуру. Если есть аббревиатуры — резервный кандидат обязан содержать хотя бы одну из них. Без них не выполняется fallback для вопроса с явным союзом `и` или соединителем `&` между требованиями. Fallback запрещён, если явно названное латинское имя/термин (Title Case) отсутствует во всех доступных чанках выбранных `ready`-документов.
5. При наличии аббревиатур кандидаты с большим количеством совпадений по ним ранжируются первыми; затем — coverage, число вхождений, дата, UUID и позиции. Без аббревиатур сохраняется прежний порядок.
6. Невалидные связи чанка и блока (включая несовпадение текста с диапазоном) отбрасываются до ранжирования.

## Ограничения и измерения

Это **экспериментальный детерминированный fallback**, а не семантический поиск. Эвристика не гарантирует правильного ответа и может создавать ложные совпадения на других корпусах. Порог `0.5` — предварительный; утверждать его можно только по before/after на 12 QA-вопросах, дополнительные negative-тесты обязательны. `I01/I02` должны продолжать давать честный отказ; отдельно требуется прямой injection-тест Ollama с доставленным вредоносным фрагментом.

Этап 0.8.2 **не меняет** `ChatService`, `Source.quote`, `MockLLM`, `OllamaLLMAdapter` или публичный API. D01/D04 пока могут отказывать из-за слишком короткого LLM-контекста; исправление — отдельный этап 0.8.3.
